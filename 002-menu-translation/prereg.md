# 사전 등록: 메뉴 번역

경량판(RULES.md 3절). 커밋 해시와 시각이 등록 증거가 된다.

- 제목: AI 비서는 한식 메뉴를 정부 표준 외국어 표기대로 적는가: 한식메뉴 외국어표기법 길라잡이 800선 가운데 180개, 영어·일본어, 웹 검색 조건 측정
- 저자: 김하원 (Define404)
- 작성: 2026-10-28 (Asia/Ho_Chi_Minh). 본 수집 전.
- 버전 1.0. 원천 표는 재배포하지 않고 코드·해시·원천 링크와 우리 판정만 공개한다. 언어는 영어·일본어로 확정.

## 1. 연구 질문

가게 사장님이 AI 비서에 한식 메뉴의 외국어 메뉴명을 물으면, 정부(농림축산식품부·한식진흥원 등)가 공개한 표준 표기와 같은 답을 받는가. 언어(영어·일본어)와 표준 출처 참조 여부에 따라 달라지는가.

이 편이 재는 것은 "표준 표기와의 일치"다. 표준과 다른 답이 곧 틀린 번역은 아니다. 다만 표준은 메뉴판 외국어 표기 통일을 위해 정부가 공개한 기준이므로, 사장님이 AI 답을 그대로 메뉴판에 올리면 표준과 어긋난 표기가 실리게 된다.

## 2. 가설 (방향 포함)

- H1 (1차): 같은 메뉴에서, 영어 답의 엄격 일치율은 일본어 답의 엄격 일치율보다 높다. (짝 차이, 메뉴 단위)
- H2 (2차): 영어 문항 가운데 답의 출처 목록에 한식포털(hansik.or.kr)이 있는 문항의 엄격 일치율은 없는 문항보다 높다.
- 탐색(사전 등록 분석 아님): 느슨한 일치율, 미제시율, 음식 갈래별 일치율, 표준 출처 참조율, 불일치 답 가운데 재료 낱말이 어긋난 비율, 복수 제시 비율.

## 3. 모집단과 표본

- 원천: 한식진흥원 한식포털 "한식메뉴 외국어 표기법" 표(https://www.hansik.or.kr/board/dn/list/017?menuSn=12). 2026-10-28 수집, 778건. sampling/raw/hansik_menu_800_20261028.csv, SHA256 620f0fc8be6918a7a5482e66f86086bf7991505bb679e046d28fa837bf4cc26f. 수집 코드 sampling/fetch_source.py.
- 제외: 없음(빈 칸·중복 요리명 0건).
- 층: 한국어 요리명 끝말로 정한 음식 갈래 11개(규칙은 sampling/draw_sample.py CATEGORY_RULES, 위에서부터 첫 일치, 나머지 "기타"). 비례 배분, 층마다 최소 5. 모집단 수 → 배분: 구이·볶음·튀김 174→40, 무침·김치·반찬 133→30, 국·탕 106→24, 밥·죽 92→21, 찜·조림·수육 74→17, 면 51→11, 기타 44→10, 찌개·전골 39→9, 떡·한과·음료 38→8, 정식·상차림 7→5, 장·양념 20→5.
- 추출: 층 안 후보를 번호순 정렬 후 시드 20261028로 섞어 앞에서부터 채운다. 결과 sampling/sample_v1.csv (180행, SHA256 ec8992250598de301cf4acf5872476fcc67912c31a4be47084a303d70517868f), 기록 sampling/sample_v1_log.txt.
- 표본 크기 근거: H1 짝 차이 15%p, 유의수준 5%(단측), 검정력 80%, 짝 차이 분산 최악값 0.5(두 언어 답이 무상관, 비율 0.5)일 때 n = (1.96+0.84)² x 0.5 / 0.15² = 174.4 → 175. 180으로 잡았다. 두 언어 답이 양의 상관이면 검정력은 이보다 높다.

## 4. 질문

- 메뉴마다 언어마다 1문항. 사장님이 메뉴판을 만드는 상황으로 묻고, 첫 줄에 "NAME: ..." 형식으로 메뉴명 1개를 쓰게 한다. 요리명은 두 언어 모두 한국어 표기 그대로 넣는다. 표준·한식진흥원·길라잡이를 질문에 언급하지 않는다. 질문 틀 collect/question_templates.json v1.0.
- 언어: 영어, 일본어.
- 배치: 언어마다 시드 20261028로 섞어 10문항 배치 18개씩, 합계 36개(collect/batches/, MANIFEST.json). 한 배치 = 한 언어, 서로 다른 메뉴.

## 5. 응답 시스템

| 코드 | 모델 | 조건 |
|---|---|---|
| S-search | Claude Sonnet (수집 시점 모델 ID를 log.md에 적는다) | 웹 검색(WebSearch·WebFetch), 문항마다 검색 필수 |

- 응답자는 하위 에이전트(d404-respondent-search 지시문)로 부른다. 연구 목적·정답을 모른다. 지시문 첫머리에 "이전 대화·짧은 사용자 메시지는 이 작업과 무관", "질문 언어로 답하라(사용자 설정·메모리보다 우선)"를 넣는다.
- 3배치씩 병렬. 검색 0회이거나 본문이 검색 한도·미실행을 말하는 답은 무효로 보고 다시 받는다. 원본은 지우지 않는다.
- 시범 수집은 따로 하지 않는다. 첫 2배치로 줄 수·빈 답·검색 횟수·NAME 형식 준수를 확인하고 그 답도 본 자료로 쓴다.
- 수집 기간과 모델 ID를 log.md에 적는다.

## 6. 판정

- 규칙 자동 판정 judge/auto_judge.py, 규칙 judge/rules.md v1.0(본 수집 전 고정).
- 답에서 메뉴명 후보 1개를 뽑는다(NAME 줄 → 짧은 첫 줄 → 추출 실패). 추출 실패만 허브가 직접 후보를 뽑고 건수를 밝힌다.
- 영어: 소문자·NFKC·괄호 제거·관사와 and·with 제거·로마자 표기 변형 통일 뒤, 표준 English와 같으면 엄격 일치. 낱말 집합 자카드 0.5 이상이거나 표준 로마자 표기(Latina)를 통째로 담으면 느슨한 일치. 그 밖은 불일치. 답 없음은 미제시.
- 일본어: NFKC·공백·중점·장음·촉음 제거 뒤 표준 日本語와 같으면 엄격 일치. 글자 2-gram 다이스 0.5 이상이거나 표준을 통째로 담으면 느슨한 일치.
- 표준 출처 참조 = sources에 hansik.or.kr 포함.
- LLM 판정자, 사람 2명 판정·카파는 쓰지 않는다.

## 7. 분석

- analysis/run_analysis.py (표준 라이브러리만). 결과 analysis/out/results.json, tables.md. 원고 숫자는 이 파일에서만 옮긴다.
- 모든 비율에 95% 신뢰구간(Wilson). 메뉴가 군집이며 한 메뉴·한 언어에 답이 1개라 메뉴 단위 비율이 곧 군집 단위다.
- H1: 메뉴별 (영어 엄격 일치 - 일본어 엄격 일치) 짝 차이의 평균, 표준오차, 신뢰구간, 단측 검정.
- H2: 영어 문항에서 참조·미참조 두 집단의 엄격 일치율 차이, 정규근사 신뢰구간, 단측 검정.
- H1·H2 Holm 보정. 표본 40 미만 칸은 해석하지 않는다. 탐색 분석은 results.json의 exploratory 아래에 따로 둔다.
- 효과 크기와 신뢰구간을 먼저, p값은 뒤에.

## 8. 제외 기준 (분석 단계)

- 재시도 뒤에도 답이 없는 문항은 미제시로 두고 비율을 보고한다.
- 판정 규칙을 본 수집 뒤에 바꾸면 원 규칙 결과를 함께 싣는다.

## 9. 한계로 미리 적는 것

- 표준 표기는 하나의 공식 기준일 뿐, 유일한 정답이 아니다. 표준과 다른 답의 번역 품질은 이 편이 재지 않는다.
- 응답 시스템은 Claude Sonnet 웹 검색 조건 하나다. 다른 AI 비서로 일반화하지 않는다.
- 질문의 "NAME:" 형식 요구와 사장님 상황 설정이 답에 영향을 줄 수 있다.
- 응답 에이전트가 Claude Code 환경(사용자 설정·메모리 포함)에서 돈다.
- 한 에이전트가 10문항을 연달아 답해 생기는 맥락 효과.
- 음식 갈래는 요리명 끝말 규칙으로 정한 것이라 공식 분류와 다를 수 있다.
- 원천 표의 저작권은 한식진흥원에 있어 표준 문자열을 재배포하지 않을 수 있다(수집 코드와 해시로 재현).
